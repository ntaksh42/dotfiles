# approval-gate 0.5.0 — 承認ゲート for Claude Code

Claude Code のエージェントに「先へ進む前に確認させて」と言えるようにする skill です。「実装前に確認させて」「作る前に見せて」と頼むと、エージェントが案を確認用の HTML 1 枚 (レビューシート) にして Crit で開きます。書いた後のコードも、「コミット前に確認したい」と頼めば差分を Crit で開きます。エージェントが決めてほしい点を [判断] コメントとして先に付けるので、それに返信し、ほかに気になる箇所があればそこへコメントして Finish Review を押せば、エージェントが反映して続きをやります。

Crit (`crit` コマンド) が必要です。

## 入れ方

### この dotfiles リポジトリを使っている場合

`claude/mods/dotfiles` の dotfiles plugin に含まれているので、個別の作業は要りません。plugin は `Install-DevTools` が導入します。

```powershell
Install-DevTools
```

### skill だけ単体で配る場合 (zip 配布)

1. `approval-gate/` フォルダを、そのまま `~/.claude/skills/` の下に置く

   ```bash
   mkdir -p ~/.claude/skills
   cp -r approval-gate ~/.claude/skills/
   ```

2. Claude Code を再起動する

3. 動作確認: 「この画面の設計、実装前に確認させて」と頼む

## 使い方

- 「**実装前に確認させて**」「**作る前に見せて**」「この案でいいか見て」 → 標準モード (設計案のシートを Crit で開く)
- 「この README に**指摘**をもらいたい」「この記事を**添削**したい」 → 原稿モード (原稿ファイルをそのまま Crit で開く。書き換えは Crit の suggestion で)

- 「**コミット前に確認したい**」「この差分を見てほしい」「PR を Crit で見たい」 → コードモード (未コミット差分・コミット範囲・PR を Crit で開く)

返信しなかった [判断] は「お任せ」になり、エージェントの推奨案で進みます。承認してもコミットは頼むまでしません。

## 使われない場面

**エージェント自身にバグを探してほしいときは使いません。** それは `code-review` の領分で、このスキルは人が見て承認するためのものです。

また、確認コストを人に払わせる道具なので、軽い確認でも起動しません。決めてほしいことが 2 問以下で見た目の差が無いとき、答えが調べれば分かるとき、人が既に方針を決めているときは、エージェントが普通に質問するか、そのまま実装します。詳しくは `SKILL.md` の「このスキルを使わない条件」を参照。
