# 出題前の試問 (preflight) — Crit で開く前に、文脈ゼロの読者で試す

シートと [判断] コメントを書いた agent は題材の全文脈を頭に持っている。だから「これで伝わる」の自己判定は構造的に甘い。
絵は載っているが判断と無関係、というシートが「絵を載せた」という形式だけで通ってしまった実例もある。
そこで、人に見せる前に **何も知らない subagent にシートとコメントだけを渡して試問する**。この試問が日本語の検査も兼ねるので、別の検査を重ねない。

対象は標準モードのシート全体 + [判断] コメント。原稿モードとコードモードは [判断] コメントだけが対象 (原稿本文やコードは人が見る現物なので試問しない)。シートのパスの代わりに、コメントが指す行の周辺をファイルパスで渡し、問い 1 は「その行を見て」に読み替える。[判断] が 0 件なら省く。

## 試問 5 問

検査員に渡すのは **シートのパス、コメント JSON のパス、読者宣言 1 行だけ**。作業の経緯、元のコード、会話の文脈は渡さない。

1. **選択肢の弁別** — 各 [判断] について、selector が指す要素 (`#p1` 等) の絵だけを見て、各選択肢を選んだ場合の画面や挙動の違いを説明せよ (見た目が違う選択肢に絵が無い判断を挙げる)
2. **引用の有無** — 各 [判断] に実測の引用 (`file:line` か実行結果) が載っているか。載っていない判断を挙げよ
3. **実質 1 択の検出** — 推奨でない選択肢を選ぶ理由が読み取れるか。読み取れない判断を挙げよ (その判断は人に決定を求めていない)
4. **音読と要約** — 音読して不自然な文、意味の取れない文を逐語で挙げよ。続けて、30 秒でシートの趣旨を 3 文で言え
5. **内輪語の列挙** — 読者宣言の許可語の外で、説明なしに使われている語や初見の造語を列挙せよ (用語欄で定義済みの語は除く)

## Agent ツールでの呼び方

`Agent` ツールで新しい subagent を立てる。`subagent_type` は general-purpose (fork は文脈を引き継ぐので使わない)。**`model=sonnet` を指定する** — 検査員の仕事は「何も知らない読者として読む」ことなので上位モデルは要らず、毎回立てる分コストが効く。**同期で結果を待つ (background にしない)。結果を受け取るまで応答を終えない** — 途中で応答を終えると、検査の結果を読まずに人へ出すことになる。prompt の雛形:

```
次の HTML は、人に判断を求める「レビュー」のシートです。JSON は、そのシートの要素にピン留めして投稿するコメントで、"[判断]" で始まるものが人に決めてほしい問いです ("selector" がピン先の要素)。
あなたは何も知らない読者として読み、5 つの問いに答えてください。
シート: /abs/path/to/review/<topic>-01.html (Read で開く)
コメント: /abs/path/to/judgments.json (Read で開く)
読者宣言: <誰が読むか> + 説明なしで使ってよい語は <語1, 語2, …> だけ

1. 各 [判断] について、selector が指すシートの要素の絵だけを見て、それぞれの選択肢を選んだ場合の画面や挙動の違いを説明してください。説明できない判断は「説明不能」と書いてください。見た目が違うのに絵が無い選択肢があれば、その判断を挙げてください。
2. 各 [判断] に実測の引用 (file:line か実行結果) が載っていますか。載っていない判断を挙げてください。
3. 推奨でない選択肢を選ぶ理由が読み取れますか。読み取れない判断を挙げてください。
4. 音読して不自然な文、意味の取れない文を逐語で挙げてください。次に、このシートの趣旨を 30 秒で 3 文で言ってください。
5. 読者宣言の許可語の外で、説明なしに使われている語や初見の造語を列挙してください (用語欄で定義済みの語は除く)。

出力は問いごとに「通過 / 落ちた判断と理由」で。直す提案は不要です。
```

読者宣言の例: `Claude Code を使う開発者。説明なしで使ってよい語は skill / plugin / HTML / Crit`。

## 判定と打ち切り

| 結果 | 扱い |
|---|---|
| 1〜3 で落ちた判断がある | 絵を加える / 判断を落とす / 言い換える (下の節)。直してから再試問 |
| 4 で不自然な文が挙がった | その文をほどく。3 文で趣旨が言えなかったら結論ボックスを書き直す |
| 5 の列挙が 3 語以上 | 言い換えてから出す。1〜2 語なら用語欄で定義する |

短いシート (1 画面程度) は 1 巡で打ち切ってよい。

再試問は **同じ検査員に差分だけを送って 1 回**。`SendMessage` で同じ agent に「直した箇所は X と Y。問い 1〜3 を再判定して」と送る。計 2 巡で打ち切る。

`SendMessage` が届かない場合 (agent が既に終了している・宛先が見つからない等) は、**新しい検査員を同じ手順で立て直し、全体を 1 回だけ試問する**。ここで諦めて試問を飛ばさない。

2 巡目の結果の読み方:

- 残ったのが軽微 (語彙 1〜2 語、語順、体言止め) なら、そのまま出してよい
- 残ったのが重大 (意味の取れない文、選択肢の弁別不能、事実の矛盾) なら、3 巡目に進まない。読者宣言に戻ってシートを書き直す。検査で磨ける限界を超えているのは、書き手の側の問題だから

## 落ちた判断の直し方

- **絵を加える** — 選択肢 A と B の見た目の違いが説明できなかったら、両方の絵をその論点の `.pt` の中に `.ab` 部品で並べ、差分に赤丸を打つ。動的な論点 (操作感、頻度) なら `./review/mock/` にモックを置いてシートの冒頭からリンクする
- **落とす** — 引用が無い判断は「まだ調べ足りない判断」。自分で `file:line` か実行結果を調べて、事実で答えが決まるなら判断ごと消す。人に残すのは決定 (好み、優先度、トレードオフの裁定) だけ
- **言い換える** — 非推奨の選択肢に「選ぶ理由」が無かったら、利点を 1 行書き加える。それでも利点が書けないなら実質 1 択なので、判断を落として推奨案で進める
- **内輪語を置き換える** — 注釈を加えるのではなく、一般語に置換する。どうしても要る語だけ用語欄 (`.gl`) で 1 行定義する
