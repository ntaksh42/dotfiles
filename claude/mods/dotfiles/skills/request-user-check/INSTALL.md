# request-user-check 0.9.1 — 報告と相談の型 for Claude Code / Codex

エージェントがユーザーに報告・相談するときの型を揃える skill です。報告は結論から書き、決めてほしい点は推奨付きの [判断] として聞きます。UI の配置のように見た目で比べる論点があるときは、比較用の HTML 1 枚 (比較シート) を書いてブラウザで開き、そのうえで [判断] を会話で聞きます。

追加のツールは要りません。比較シートの検査に python3 を使います。

## 入れ方

### この dotfiles リポジトリを使っている場合

`claude/mods/dotfiles` の dotfiles plugin に含まれているので、個別の作業は要りません。plugin は `Install-DevTools` が導入します。

```powershell
Install-DevTools
```

### skill だけ単体で配る場合 (zip 配布)

1. `request-user-check/` フォルダを、そのまま `~/.claude/skills/` (Codex なら Codex の skills ディレクトリ) の下に置く

   ```bash
   mkdir -p ~/.claude/skills
   cp -r request-user-check ~/.claude/skills/
   ```

2. エージェントを再起動する

3. 動作確認: 「この画面の設計、実装前に確認させて」と頼む

## 使い方

頼まなくても、エージェントは報告や相談のたびにこの型を使います。

- 作業の完了報告・調査結果 → 結論から書いた報告。会話で 10 行を超えるなら、表にまとめた HTML の報告シートで見せる
- 方針の相談・実装前の確認 → 報告 + [判断] (Claude Code なら質問ツールで選択肢を出す)
- 「**作る前に見せて**」「どっちのレイアウトがいいか比べたい」 → 比較シートをブラウザで開き、[判断] は会話で聞く
- 「**コミット前に確認したい**」 → 変更の要点と、判断の要る行を示して確認する

返事をしなかった [判断] は、エージェントの推奨案で進みます。承認しても、コミットは頼むまでしません。

## 使われない場面

報告する相手のいない無人実行と、短い相槌や挨拶への返事では使いません。
