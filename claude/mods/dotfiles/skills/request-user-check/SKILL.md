# request-user-check — 報告と相談の型

ユーザーへの報告と相談をすべてこの型で出す。読み手が最初の数行で状況をつかみ、決めることだけを決めて先へ進めるようにするため。
**Input**: 報告する結果、または決めてほしい論点。
**Output**: 会話での報告・相談。長くなる報告は HTML の報告シート、見た目で比べる論点があれば `./review/<topic>.html` の比較シートを加える。

Claude Code でも Codex でも同じ手順で動く。ツール名は環境に合わせて読み替える (質問ツールが無ければ会話で聞く、`Agent` ツールが無ければ試問を省く)。

## 形を選ぶ

| 状況 | 形 |
|---|---|
| 報告だけ (決めてほしいことが無い) | **報告**: 会話で結論から書く |
| 決めてほしいことがあり、文章だけで選べる | **相談**: 報告 + [判断]。質問ツールがあればそれで聞く |
| 報告・相談が会話で 10 行を超える、または 3 項目以上の一覧・比較になる | **報告シート**: 中身を HTML 1 枚にまとめて見せ、会話には結論 1 文と [判断] だけ書く |
| 見た目で比べる論点がある (UI の配置・レイアウト・画面遷移の A/B) | **シート**: HTML の比較シートを開き、[判断] は会話で聞く |
| 長文の原稿 (記事・README・レポート) を渡す | **原稿**: 原稿ファイルそのものを渡して開き、指摘は会話で受ける。要約に組み直さない |
| 書いたコードの承認を取る (コミット前・方針が分かれる変更の後) | **差分**: 変更の要点と、判断の要る行を `file:line` で示して [判断] を付ける |

ユーザーは長い文章を会話で読むのが負担なので、会話に書く分量を 10 行までに抑え、超える分は報告シートに移す。比較シートを作るのは、絵が無いと人が想像で補ってしまう論点があるときだけにする。

## 報告の書き方

1. **1 文目は結果** — 頼まれたことができたか、何が分かったか。経緯や手順から書き始めない
2. **要点** — 何を変えたか、何を根拠にそう言えるか。`file:line` や実行結果を引く。必要な分だけ
3. **[判断]** (相談のときだけ) — 下の書式で 3±1 件まで
4. **注意点** — 失敗したテスト、飛ばした作業、想定と違った挙動。あれば必ず書き、無ければ書かない

- 箇条書きと見出しは、読みやすくなるときだけ使う。短い報告は普通の文章で書く
- 作業の中で作った呼び名を説明なしに使わない
- 「調べれば分かること」を人に聞かない。自分で調べて報告に書く

## [判断] の書式

1 件 = 1 つの判断。人がその文面だけで即答できる形にする。

```
[判断] <問い 1 行>
A: <案> — <利点> / <代償>
B: <案> — <利点> / <代償>
推奨: A (<理由>) 根拠: <file:line か実行結果>
```

- **非推奨の案にも利点を書く** (`/` の左)。利点が書けないなら実質 1 択なので、[判断] にせず推奨で進めて報告に書く
- 判断に要る数値は文面の中に書く。シートや別の箇所へ探しに行かせない
- シートがあるときは、問いの頭に論点の番号 (①②③) を付けて、どの絵の話かを示す
- 質問ツール (Claude Code の `AskUserQuestion` 等) があればそれで聞く。推奨の案を先頭に置き、ラベルに「(推奨)」と付ける。1 回の質問は 4 件まで
- 質問ツールが無ければ、会話に [判断] をそのまま書き、「返事が無い判断は推奨で進めます」と 1 回だけ添える

## 最重要禁則

- **承認の前に先へ進まない** — 実装前の相談なら、返事が来るまで実装しない。コミット前の確認なら、コミットも次の変更もしない
- **承認されてもコミットは依頼があるまでしない** — 承認はコミットの依頼ではない
- **事実を人に聞かない** — 各 [判断] に `file:line` か実行結果を添える。人に残すのは決定 (好み・優先度・トレードオフの裁定) だけ
- **[判断] は 3±1 件まで。5 件以上出さない** — 人の判断コストが本体。すべてに推奨を付け、返事が無くても進められる形にする
- **結果を盛らない** — 失敗・未確認・回避したことは、そのまま書く

## 報告シートの手順 (会話で書くと長くなるとき)

1. **書く** — `assets/sheet-template.html` ではなく `assets/report-template.html` を埋める。要点は表にして 1 行 1 項目、根拠は `file:line` か実行結果を添える。段落は 2 文まで。経緯やログは `<details>` に畳む。[判断] はシートに書かない
2. **置いて見せる** — 環境変数 `ORCA_CHAT_SCRATCH_DIR` があれば (Orca のチャット)、そのフォルダに毎回新しい名前 (`<topic>-<4 桁の英数字>.html`) で保存し、会話に `::orca-visual{file="<ファイル名>" title="<タイトル>"}` を単独の行で書く。無ければ一時ディレクトリに保存してブラウザで開き、パスも会話に書く
3. **会話に書く** — 結論 1 文、シートの表示 (またはパス)、[判断] だけ。シートの中身を会話で繰り返さない

## 比較シートの手順 (見た目で比べる論点があるとき)

`<skill dir>` は、この SKILL.md が置かれているディレクトリを指す。plugin として入れた場合は `${CLAUDE_PLUGIN_ROOT}/skills/request-user-check/`、skill として置いた場合はその置き場所。分からなければ、この SKILL.md 自身のパスから求める。

1. **現物を把握する** — 既存 UI ならスクショかコードから忠実に再現する。ゼロからの構想なら図解でよい
2. **シートを書く** — `references/sheet-spec.md` を Read し、`assets/sheet-template.html` を埋めて `./review/<topic>.html` に保存する。版番号は付けず、やり直しでも同じファイルを上書きする。論点ごとに絵を包む要素へ `id="p1"`, `id="p2"`, … を振り、赤の ①②③ を打つ。**選択肢の対立軸は両方絵にする**
3. **[判断] の JSON を書く** — `[{"selector": "#p1", "body": "[判断] …"}]` の形で scratchpad (無ければ一時ディレクトリ) に保存する。`selector` はその判断が指す論点の id
4. **機械検査** — `python3 "<skill dir>/assets/check-sheet.py" ./review/<topic>.html --comments <json>` を実行する。`TODO` の残り、相対 URL、論点の無い [判断]、推奨の書き忘れ、文字の多すぎを検出する。NG が出たら直す
5. **試問** — `Agent` ツール (subagent) があれば、`references/preflight.md` の 5 問を文脈ゼロの subagent に出す。同期で結果を待ち、落ちた件は絵を足す・判断を落とす・言い換える。計 2 巡で打ち切る。subagent を立てられない環境では省く
6. **開いて聞く** — シートをブラウザで開く (Windows は `Start-Process <path>`、macOS は `open`、Linux は `xdg-open`)。開けない環境 (リモートのコンテナ等) では、シートのパスを伝えるか、ファイルを渡す手段があればそれで渡す。続けて会話で [判断] を聞く (上の書式)
7. **反映する** — 返事に沿って直す。返事の無い [判断] は推奨で確定する。設計が変わる指摘なら同じファイルを上書きして開き直し、捨てた案はシート内に取り消し線で残す
8. **残す** — シート HTML は消さない。git 管理下ならシートの commit を勧める (「なぜこの設計か」の答えになる)。反映後のコードの commit は人に確認してから

## Gotchas

- **シートに問いを並べない** — 問いは会話の [判断] に置き、シートには絵・対比表・根拠だけを載せる。両方に書くと、人は同じ問いを 2 か所で読むことになる。論点の場所は ①②③ の印だけで示す
- **現物と乖離したモックを描かない** — 既存画面に手を加えるなら、現行 UI の忠実な再現が信頼の根になる
- **シートは self-contained にする** — 相対 URL を使わない。画像は data URI か https の絶対 URL。モックへのリンクは `file://` の絶対 URL (Windows はスラッシュ 3 本: `file:///C:/path/to/mock.html`。空白は `%20`)
- **試問の subagent を background で立てない** — 結果が返る前に応答を終えると、検査をしないまま人に出すことになる
