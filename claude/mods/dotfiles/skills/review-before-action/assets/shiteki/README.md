# 指摘モード kit — 原稿へ移植する手順 (agent 向け)

読者: この skill を動かす agent。原稿 (記事・README・長文レポート) を HTML のまま人に見せ、段落単位の指摘だけを【レビュー回答】固定形で受け取るための kit。直すのは agent。

- `kit-template.html` — 見本原稿 + 指摘層。file:// で開くだけで動く (外部 JS なし)
- 回答の形は `../../references/reply-format.md` (固定形の契約)。kit の [貼り付ける文章を作る] がこの形を出す
- ボタン文言は変えない (「コメント一覧」「貼り付ける文章を作る」— 下の案内文と揃うため)

## 1. 原稿へ層を移植する (2 通り、どちらでも同じ)

kit の body には `<!-- ═══ 指摘層 (前半) ═══ -->` と `<!-- ═══ 指摘層 (後半) ═══ -->` のコメント対が 2 組ある。

**A. 原稿 HTML に層を移植する** (原稿の様式を保ちたい時)

1. 前半ブロック (`#akTop` の topbar + `#akQs` の設問) を原稿の `<body>` 直後へコピー
2. 後半ブロック (`<style>` + UI + `<script>`) を `</body>` 直前へコピー
3. 原稿の `<body>` に `data-shiteki="shiteki-<案件slug>"` を付ける
4. 原稿本文の HTML には手を入れない。層は実行時に `data-blk` 等の属性とピンを重ねるだけ

**B. kit の `<article>` へ原稿を流し込む** (原稿が Markdown 等で HTML 様式を持たない時)

1. `kit-template.html` を `./review/<topic>-01.html` にコピー
2. `<article>` の中身を原稿の HTML に丸ごと差し替える (`<h1>` から末尾まで)
3. `<head>` の見本原稿用 `<style>` は原稿に合わせて直してよい
4. `data-shiteki` を案件の値に変える

指摘の対象になるブロックは `p, h2, h3, li, figure, blockquote, pre, aside, table` (script 冒頭の `SEL`)。画像だけの `figure` は抜粋が空になるので `figcaption` を付ける。

## 2. `data-shiteki` (案件キー)

- `<body data-shiteki="shiteki-<案件slug>">`。値は回答 1 行目の `【レビュー回答】<label>` になり、同時に下書き (指摘・全体コメント・設問の選択) の localStorage キーになる
- **案件ごとに一意な固定文字列**にする。使い回すと前の案件の下書きが復元される。再往復 (`-02.html`) は別の値にする (`shiteki-<slug>-02` 等)
- 実行時に生成しない (`crypto.randomUUID` 不可 — file:// 以外で開かれると undefined)

## 3. `#akQs` の設問を差し替える

- `.ak-qcard` を 3±1 問。0 問なら `#akQs` ごと消してよい (回答に Q 行が出ないだけ)
  - クラス名は `.ak-qcard`。**標準モードの `.qcard` とは別物**なので、sheet-spec.md の CSS をここへ持ち込まない
- 各 qcard: `<p class="ak-qt">N. 問い</p>` + `<label><input type="radio" name="qN" value="A" checked> <b>A.</b> 選択肢 <span class="ak-rec">推奨</span></label>` …
  - `name` は qcard ごとに一意 (`q1`, `q2`, …)。回答行の `Qn.` は qcard の並び順で振られる (`.ak-qt` の先頭「N. 」は剥がされる)
  - 推奨案に `checked` を付ける (未選択 = お任せ、で人が何もしなくても進める)。人が「選ばずにこちらへ任せる」で外すと `(未選択 = お任せ)` になる
  - 「別案」の選択肢 (value="other") は置かない。別の案は全体コメントに書いてもらう (「選ばずにこちらへ任せる」のリンクに案内が付く)
  - 選択肢の文は `<b>A.</b>` の後に 1 行 (利点/代償)。回答行には label の文が `A — <選択肢>` として載る (「推奨」バッジと `A.` は自動で剥がす)
- 出題規律は SKILL.md のとおり (事実を人に聞かない・対立軸を両方見せる・自由記述に構造を書かせない)。長文モードでは設問が原稿の冒頭に来てよい — 原稿全文が同じ画面にあるので読後に戻って答えられる

## 4. 開催中は原稿を変えない

ブロック番号 `#N` は原稿の DOM 順の連番 (`data-blk`)。開催中に段落を足す・消す・並べ替えると、人の下書きと貼り戻された回答の番号が無言でずれる。直したくなったら回答を待ってから `-02.html` を別の `data-shiteki` で作る。

反映するときは、回答の `#N` を HTML 側の番号と突き合わせる。指摘済みのブロックは左肩の赤い番号札に `#N` が常時出る。未指摘のブロックもホバーすると右上に `#N` が出る。同じ番号を DOM 順に数え直すなら `document.querySelectorAll("[data-blk]")` の `N-1` 番目。

## 5. 回答の読み方

```
【レビュー回答】shiteki-<slug>
Q1. <問い>: A — <選択肢>
Q2. <問い>: (未選択 = お任せ)
全体へのコメント: <自由記述 | (なし)>
## 指摘
#3 [短くする] <ひとこと>
#7 [言い換える] 「なぞった文字列 (先頭 40 字)」 <ひとこと>
#12 [ここは良い]
---
上の回答を反映して作業を続けてください。お任せの項目は推奨案で確定してください。
```

- `## 指摘` は指摘が 1 件以上ある時だけ出る。行は DOM 順 (同じブロック内は付けた順)
- `「…」` の引用があれば、その文字列を含む箇所への指摘。無ければブロック全体への指摘
- チップだけの行 (`#12 [ここは良い]`) は、そのチップが指摘の全て。ひとことが併記されていればひとことが正

## 6. 移植後の確認 (人に見せる前に目視で通す)

指摘モードは生成器を通さない手作業の移植なので、標準モードの `check-sheet.py` にあたる機械検査が無い。
下は無言で壊れる不備だけを並べたもの。**ブラウザで 1 度開いて、上から順に確かめる。**

- [ ] `data-shiteki` を案件固有の値に変えた (`shiteki-SLUG` のままにしない。使い回すと前の案件の下書きが復元される)
- [ ] 本文の段落をタップすると、左肩に赤い番号札 `#N` が出る (出なければ `SEL` に合う要素が無い = 指摘を付けられない)
- [ ] `#akQs` の各 `.ak-qcard` で `name="qN"` が問いごとに一意 (重複すると別の問いの選択肢を奪い合う)
- [ ] 推奨案の radio に `checked` が付いている (未選択のまま出すと、人が何もしなければ回答に載らない)
- [ ] [貼り付ける文章を作る] を押すと `【レビュー回答】<data-shiteki の値>` で始まるテキストが出る
- [ ] 原稿に `crypto.randomUUID` を足していない (file:// で undefined になり下書きが全滅する)

## 7. 人への案内文の例

```
./review/<topic>-01.html をブラウザで開いてください (file:// のままで動きます)。
- 冒頭の「先に決めてほしいこと」に答える (そのままでも推奨で進めます)
- 気になる段落をタップ、または文字をなぞって「選択範囲にコメント」→ チップ + ひとこと
- 右上の「コメント一覧」で全体コメントを書けます
- 最後に右上の [貼り付ける文章を作る] → 出たテキストをこのターミナルに貼って Enter
途中で閉じても下書きはブラウザに残ります (同じファイルを開き直せば復元)。
```
