# 出題前の試問 (preflight) — シートを開く前に、文脈ゼロの読者で試す

シートを書いた agent は題材の全文脈を頭に持っている。だから「これで伝わる」の自己判定は構造的に甘い。
絵は載っているが問いと無関係、というシートが「絵を載せた」という形式だけで通ってしまった実例もある。
そこで、人に見せる前に **何も知らない subagent にシートだけを渡して試問する**。この試問がシートの日本語検査も兼ねるので、別の検査を重ねない。

対象は 3 モードすべて。標準モードはシートの全体、指摘モードと添削モードは冒頭の問いブロックと導入文が対象になる (原稿本文は人が直す対象なので試問しない)。

## 試問 5 問

検査員に渡すのは **シートのパスと読者宣言 1 行だけ**。作業の経緯、元のコード、会話の文脈は渡さない。

1. **選択肢の弁別** — 各問について、それぞれの選択肢を選んだ場合の画面や挙動の違いを、このシートだけから説明せよ。続けて、シートの下の回答フォームだけを見て (上の本文を見ずに)、各選択肢の違いが絵で分かるか答えよ (見た目が違う選択肢に絵が無い問いを挙げる)
2. **引用の有無** — 各問に実測の引用 (`file:line` か実行結果) が載っているか。載っていない問いを挙げよ
3. **実質 1 択の検出** — 推奨でない選択肢を選ぶ理由が読み取れるか。読み取れない問いを挙げよ (その問いは人に判断を求めていない)
4. **音読と要約** — 音読して不自然な文、意味の取れない文を逐語で挙げよ。続けて、30 秒で趣旨を 3 文で言え
5. **内輪語の列挙** — 読者宣言の許可語の外で、説明なしに使われている語や初見の造語を列挙せよ (用語欄で定義済みの語は除く)

## Agent ツールでの呼び方

`Agent` ツールで新しい subagent を立てる。`subagent_type` は general-purpose (fork は文脈を引き継ぐので使わない)。**`model=sonnet` を指定する** — 検査員の仕事は「何も知らない読者として読む」ことなので上位モデルは要らず、毎回立てる分コストが効く。**同期で結果を待つ (background にしない)。結果を受け取るまで応答を終えない** — 途中で応答を終えると、検査の結果を読まずに人へシートを出すことになる。prompt の雛形:

```
次の HTML は、人に判断を求める「レビュー」のシートです。あなたは何も知らない読者として読み、5 つの問いに答えてください。
シート: /abs/path/to/review/<topic>-01.html (Read で開く)
読者宣言: <誰が読むか> + 説明なしで使ってよい語は <語1, 語2, …> だけ

1. 各問について、それぞれの選択肢を選んだ場合の画面や挙動の違いを、このシートだけから説明してください。説明できない問いは「説明不能」と書いてください。続けて、シートの下の回答フォーム (id="akForm") だけを見て、各選択肢の違いが絵で分かるか答えてください。見た目が違うのに絵が無い選択肢があれば、その問いを挙げてください。
2. 各問に実測の引用 (file:line か実行結果) が載っていますか。載っていない問いを挙げてください。
3. 推奨でない選択肢を選ぶ理由が読み取れますか。読み取れない問いを挙げてください。
4. 音読して不自然な文、意味の取れない文を逐語で挙げてください。次に、このシートの趣旨を 30 秒で 3 文で言ってください。
5. 読者宣言の許可語の外で、説明なしに使われている語や初見の造語を列挙してください (用語欄で定義済みの語は除く)。

出力は問いごとに「通過 / 落ちた問いと理由」で。シートを直す提案は不要です。
```

読者宣言の例: `Claude Code を使う開発者。説明なしで使ってよい語は skill / plugin / HTML / file:// / クリップボード`。

## 判定と打ち切り

| 結果 | 扱い |
|---|---|
| 1〜3 で落ちた問いがある | 絵を加える / 問いを落とす / 言い換える (下の節)。直してから再試問 |
| 4 で不自然な文が挙がった | その文をほどく。3 文で趣旨が言えなかったら結論ボックスを書き直す |
| 5 の列挙が 3 語以上 | 言い換えてから出題する。1〜2 語なら用語欄で定義する |

添削モードは問いが 0 なので試問を省く。短い原稿 (1 画面程度) の指摘モード・標準モードは 1 巡で打ち切ってよい。

再試問は **同じ検査員に差分だけを送って 1 回**。`SendMessage` で同じ agent に「直した箇所は X と Y。問い 1〜3 を再判定して」と送る。計 2 巡で打ち切る。

`SendMessage` が届かない場合 (agent が既に終了している・宛先が見つからない等) は、**新しい検査員を同じ手順で立て直し、シート全体を 1 回だけ試問する**。文脈を持たない読者による検査という要件は満たせるので、差分だけを送る形にこだわらない。ここで諦めて試問を飛ばさない。

2 巡目の結果の読み方:

- 残ったのが軽微 (語彙 1〜2 語、語順、体言止め) なら、そのまま出題してよい
- 残ったのが重大 (意味の取れない文、選択肢の弁別不能、事実の矛盾) なら、3 巡目に進まない。読者宣言に戻ってシートを書き直す。検査で磨ける限界を超えているのは、書き手の側の問題だから

## 落ちた問いの直し方

- **絵を加える** — 選択肢 A と B の見た目の違いが説明できなかったら、両方の絵を `.ab` 部品で並べ、差分に赤丸を打つ。同じ絵を回答フォームの選択肢 (`.thumb`) にもコピーする。動的な論点 (操作感、頻度) なら `./review/mock/` にモックを置いてシートの冒頭からリンクする
- **落とす** — 引用が無い問いは「まだ調べ足りない問い」。自分で `file:line` か実行結果を調べて、事実で答えが決まるなら問いごと消す。人に残すのは決定 (好み、優先度、トレードオフの裁定) だけ
- **言い換える** — 非推奨の選択肢に「選ぶ理由」が無かったら、利点を 1 行書き加える。それでも利点が書けないなら実質 1 択なので、問いを落として推奨案で進める
- **内輪語を置き換える** — 注釈を加えるのではなく、一般語に置換する。どうしても要る語だけ用語欄 (`.gl`) で 1 行定義する
