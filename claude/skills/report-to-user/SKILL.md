# report-to-user — 報告・相談・HTMLレポート

結果を先に伝え、人が判断に必要な根拠を見渡せる形にする。Claude Code / Codex 共通。`<skill dir>` はこの SKILL.md のあるディレクトリで、スクリプトや参照資料はそこから相対で解決する。

## 返す形を選ぶ

返信を書き始める前に形を決める。会話に長文を書いてからシートへ移すと、同じ内容を 2 回書くことになる。

| 状況 | 形 |
|---|---|
| 短い結果・質問への回答 | 会話で結論、必要な根拠、注意点を返す |
| 記事・READMEなど原稿そのものを依頼された | 原稿ファイルを渡す。報告シートへ変換しない |
| 会話で書くと長くなる報告・相談 (会話で結論の 1 行を除いて 5 行か 300 字 (空白とコードブロックを除く) を超えるか、6 項目以上の一覧・比較・指摘・問題・テスト結果・変更点。5 項目までは会話の箇条書きでよい) | **報告シート**。`scripts/new-sheet.py` で作る (下の「報告シート」) |
| HTML保存・レポート保存の明示依頼、または項目が多く相互参照が要る調査 | **詳細レポート**。下の手順でMarkdownから生成する |
| UIの配置・レイアウト・画面遷移を見て選ぶ必要がある | **比較シート**。`references/comparison-sheet.md` を読む |
| 文章で選べる方針や優先度の相談 | 推奨付きの **[判断]**。判断材料が多ければ報告シートの「要判断」に書く |
| コードの確認 | 要点と最初に見る `file:line` を示す。大量の指摘は報告シートへ |

行数や件数だけでHTML化しない。数件のテスト結果が短く読めるなら会話でよい。ユーザーが形式を指定した場合はそれを優先する。比較シートと報告シートの文字数制限を詳細レポートへ適用しない。

## シートを出したときの会話

報告シート・比較シート・詳細レポートを出したら、会話には **結論 1 文とシートの場所だけ** を書く。[判断]・推奨・注意点・項目の一覧はシートに書き、会話で繰り返さない。答えは会話で受ける。シートの中身を会話に要約し直さない。

## 報告の核

- 最初の1文に結果と要点を書く。経緯から始めない。
- 根拠はファイルパスと行番号、実行結果、参照URLで示す。確認済み・推測・未検証を区別する。
- 失敗したチェック、省略した検証、残った問題は明記する。
- 指摘・理由・推奨対応・コードや差分を欠落させない。強調を絞っても情報は削らない。試行錯誤を逐語で残す必要はない。
- 表は比較や一覧に使う。図は要点を形で見せるために使い、報告シートには既定で 1 枚置く (下の「図の選び方」)。
- 色だけで状態を示さず、要対応・確認済み・未検証などの文字を添える。重大度と種別のテーマ色を混同しない。

## [判断] — 決めてもらう必要があるときだけ

シートを出さない短い相談では、会話に次の形で書く。シートを出すときは、同じ中身をシートの「要判断」(比較シートでは論点の下の推奨の行) に書き、会話には書かない。

```text
[判断] <問い1つ>
推奨: <案の名前> — <理由と根拠>
他案: <案の名前> — <利点> / <代償>
```

事実は先に自分で調べ、人には好み・優先度・トレードオフを聞く。聞くことが無ければ [判断] を書かない。報告の締めに問いを足すために判断を作らない。他案に利点がなければ実質1択なので、判断を増やさず既存の権限内で進める。問いは通常1〜3件、多くても4件。

質問ツールは、シートを出さないときだけ使う。推奨を先頭にして尋ねる。シートを出したときに質問ツールを開くと、ダイアログがシートを隠し、問いが 2 か所に出る。**返事がないことは承認ではない。** 実装前の合意など必要な承認は返答を待つ。既に承認された作業や、その範囲内の可逆な作業に確認を追加しない。承認待ちと独立した調査・検証は進めてよい。コミット・push・公開はそれぞれ依頼の範囲に従い、設計承認だけを実行依頼と解釈しない。

## 詳細レポート

1. `references/html-report.md` を読み、種別・保存先・表示経路を決める。
2. `references/markdown-syntax.md` の記法で本文をUTF-8の一時ファイルへ書く。冒頭に結論と次の行動、本文に全指摘・根拠・対応・決めてほしいことを載せる。
3. `pwsh -NoProfile -File "<skill dir>/scripts/New-HtmlReport.ps1"` で生成する。自動採番・テーマ・目次・ダークモードは生成器に任せる。
4. 出力HTMLの件数、コード、リンク、未置換の雛形を確認し、ブラウザか画像で表示を確認する。開けない場合は表示未検証と伝える。
5. 会話は「シートを出したときの会話」に従う。

## 報告シート (既定)

会話で書くと長くなる報告・相談の既定の形。HTML は手で書かず、短い Markdown を `scripts/new-sheet.py` に渡す。生成器が雛形への流し込み・検査・保存先の決定まで行う。読み手が最初の画面だけで、結果・自分のすること・決める事項を分かるように書く。

1. 先に要点を 1 つ決める。書式は `references/sheet-input.md` (初回だけ読む)。
2. タイトルを結論にする。`# <状態の語> | <結論 1 文>`。状態の語は読み手がすることで選ぶ: 対応不要 / 要判断 n 件 / 要対応 / 未完了。作業報告・調査結果・質問への回答のどれにも同じ語を使う。続く行には、結論を言い換えない補足があるときだけ 1 文を書き、`次:` に読み手がすることを 1 行で書く。
3. 図は既定で 1 枚置く (` ```svg ` のフェンス。多くても 2 枚)。型は下の「図の選び方」から選び、要点の要素だけを `<g class="key">` で包む。省くのは内容に形が無いときだけ。
4. 要点の箇条書きは 5 個まで。6 個以上になるなら `## 項目` に書く。
5. 決めてもらう事項があれば、1 問ずつ `## 要判断: <問い>` に書き、1 行目を `推奨:` にする。他案は利点のある案があるときだけ、利点と代償を添えて書く。
6. `## 項目` は 1 行 1 項目。根拠は `根拠:` の続き行に、file:line や実行結果など示せるものがある行だけ書く。これから誰かがすることのある行にだけ `対応:` を書く。「特になし」「引き続き注視」「念のため確認」など、することの無い埋め草は書かない。ラベルは行によって状態が違うときだけ付け、先に対応すべき行だけ `[先に対応]` にする。
7. 文字の上限は本文 800 字、結論 (タイトル) 80 字、表のセル 60 字 (根拠の行は数えない)。経緯・手順・ログは `## 付録` に畳み、読み手の判断に要る情報は畳まない。
8. 生成する。Bash なら 1 回の呼び出しで済む:
   ```bash
   python "<skill dir>/scripts/new-sheet.py" - --name <英数字の題> <<'EOF'
   # 要判断 1 件 | ...
   EOF
   ```
   PowerShell では here-string をパイプで渡す。`NG` が出たら直して作り直す。`??` は読んで、必要なものだけ直す。
9. 生成器が出したシートの場所 (Orca では `::orca-visual` の行) を会話に貼り、「シートを出したときの会話」に従う。

### 図の選び方

要点が持つ形に合わせて型を 1 つ選ぶ。文字を消しても形だけで意味が通る図にし、説明は図のラベルに書く。

| 要点の形 | 型 | 描き方 |
|---|---|---|
| 変更の前と後で何かが違う | 前後 | 同じ配置の図を左右に並べ、変わった要素だけ赤くする |
| 処理や手順のどこかで起きている | 流れ | 箱を矢印でつなぎ、問題や変更のある段だけ赤くする |
| 部品のどれかに関わる | 構成 | 部品を入れ子や隣り合わせの箱で描き、該当の部品だけ赤くする |
| 数や大きさに差がある | 量 | 横棒を同じ目盛りで並べ、数値を棒の端に書く。注目の 1 本だけ赤くする |
| 多くの項目に済み・未了が混ざる | 状態の格子 | 項目を升目に並べ、状態を文字で入れる。先に対応する升だけ赤くする |

箱に見出しの文字を入れて並べただけの図は、表と同じ内容になるので描かない。どの型にも当てはまらないときだけ図を省く。

## シートの見せ方 (環境別)

| 環境 | 保存と表示 |
|---|---|
| `ORCA_CHAT_SCRATCH_DIR` がある | 報告シートは new-sheet.py が scratch に保存し、会話に貼る `::orca-visual{...}` の行を出す。詳細レポートは scratch 内の一意な `<topic>-<英数字>.html` へ `-OutputPath` と `-NoOpen` で保存し、同じ形の行を単独行で返す。通常は別ブラウザを開かない。永続保存も依頼されていれば設定先にも保存する |
| 通常のローカル環境 | 報告シートは一時ディレクトリの `report-sheets/` (`--out` で変えられる)。詳細レポートは `output-config.toml` の設定先。比較シートは `./review/<topic>.html`。ブラウザを開ける場合は表示し、会話にも絶対パスのリンクを返す |
| 表示できない環境 | 保存だけして、絶対パスのリンクまたは利用可能なファイル受け渡し手段で渡す。表示未検証を明記 |

環境の表示規約・ユーザー指定を優先する。Codexの会話には `[タイトル](/absolute/path/report.html)` 形式でリンクする。HTML内のローカル成果物リンクは `file:///C:/path/...` 形式で、空白などをURLエンコードする。

## 参照資料

- `references/sheet-input.md` — 報告シートの本文 (new-sheet.py の入力) の書式
- `references/html-report.md` — 詳細レポートの生成・保存・検証
- `references/markdown-syntax.md` — 表、コード、SVG、Mermaid、バッジ、進捗バー
- `references/comparison-sheet.md` — UI比較、機械検査、表示、返答の反映
- `references/sheet-spec.md` — 比較シートのレイアウトと文章規約
- `references/preflight.md` — 比較シートを初見の読者に試問する手順

`html-report` / `save-report` が同時に選ばれても、同じ報告を重複生成しない。本スキルを入口とし、形式・保存先・承認の扱いはこの統合手順に揃える。既存スキルの設定は変更しない。
