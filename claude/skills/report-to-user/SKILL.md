# report-to-user — 報告・相談・HTMLレポート

結果を先に伝え、人が判断に必要な根拠を見渡せる形にする。Claude Code / Codex 共通。`<skill dir>` はこの SKILL.md のあるディレクトリで、スクリプトや参照資料はそこから相対で解決する。

## 返す形を選ぶ

| 状況 | 形 |
|---|---|
| 短い結果・質問への回答 | 会話で結論、必要な根拠、注意点を返す |
| 記事・READMEなど原稿そのものを依頼された | 原稿ファイルを渡す。報告シートへ変換しない |
| 会話で書くと長くなる報告・相談 (3項目以上の一覧・比較・指摘、複数のテスト結果) | **報告シート**。`assets/report-template.html` を埋める (旧方式。下の「報告シート」) |
| HTML保存・レポート保存の明示依頼、または項目が多く相互参照が要る調査 | **詳細レポート**。下の手順でMarkdownから生成する |
| UIの配置・レイアウト・画面遷移を見て選ぶ必要がある | **比較シート**。`references/comparison-sheet.md` を読む |
| 文章で選べる方針や優先度の相談 | 推奨付きの **[判断]**。判断材料が多ければ報告シートを添える |
| コードの確認 | 要点と最初に見る `file:line` を示す。大量の指摘は報告シートへ |

行数や件数だけでHTML化しない。数件のテスト結果が短く読めるなら会話でよい。ユーザーが形式を指定した場合はそれを優先する。比較シートと報告シートの文字数制限を詳細レポートへ適用しない。

## 報告の核

- 最初の1文に結果と要点を書く。経緯から始めない。
- 根拠はファイルパスと行番号、実行結果、参照URLで示す。確認済み・推測・未検証を区別する。
- 失敗したチェック、省略した検証、残った問題は明記する。
- 指摘・理由・推奨対応・コードや差分を欠落させない。強調を絞っても情報は削らない。試行錯誤を逐語で残す必要はない。
- 表は比較や一覧に、図は流れ・構造・前後・量の関係が表だけでは伝わらないときに使う。
- 色だけで状態を示さず、要対応・確認済み・未検証などの文字を添える。重大度と種別のテーマ色を混同しない。

## [判断] — 決めてもらう必要があるときだけ

```text
[判断] <問い1つ>
推奨: <案の名前> — <理由と根拠>
他案: <案の名前> — <利点> / <代償>
```

事実は先に自分で調べ、人には好み・優先度・トレードオフを聞く。他案に利点がなければ実質1択なので、判断を増やさず既存の権限内で進める。問いは通常1〜3件、多くても4件。比較シートがあれば番号と論点名を揃える。

質問ツールが使えるなら推奨を先頭にして尋ねる。無ければ会話で聞く。**返事がないことは承認ではない。** 実装前の合意など必要な承認は返答を待つ。既に承認された作業や、その範囲内の可逆な作業に確認を追加しない。承認待ちと独立した調査・検証は進めてよい。コミット・push・公開はそれぞれ依頼の範囲に従い、設計承認だけを実行依頼と解釈しない。

## 詳細レポート

1. `references/html-report.md` を読み、種別・保存先・表示経路を決める。
2. `references/markdown-syntax.md` の記法で本文をUTF-8の一時ファイルへ書く。冒頭に結論と次の行動、本文に全指摘・根拠・対応を載せる。
3. `pwsh -NoProfile -File "<skill dir>/scripts/New-HtmlReport.ps1"` で生成する。自動採番・テーマ・目次・ダークモードは生成器に任せる。
4. 出力HTMLの件数、コード、リンク、未置換の雛形を確認し、ブラウザか画像で表示を確認する。開けない場合は表示未検証と伝える。
5. 会話は結論1文、成果物リンク、重要な注意点、必要なら [判断] に絞る。本文を重複して列挙しない。ただし会話だけでも必要な結論を把握できるようにする。

## 報告シート (既定。旧方式)

会話で書くと長くなる報告・相談の既定の形。詳細レポートの生成器は使わない。

1. `assets/report-template.html` の TODO を埋める。骨格は 要点のタイトル → 結論 1 文 → 図 (形が要るときだけ。インライン SVG) → 1 行 1 項目の表 → 要判断の表 (判断があるときだけ) → 注意点 → 畳み付録。先に要点を 1 つ決め、図では要点だけを `class="key"` で赤くする。
2. 文字の上限は本文 600 字、結論 80 字、表のセル 60 字。段落は 2 文まで。経緯・手順・ログは `<details>` に畳み、読み手の判断に要る情報は畳まない。
3. 決めてもらう事項があれば「要判断」の表に 1 問 1 行で書く (番号・問い・推奨と理由・他案の利点と代償)。回答用の入力欄 (radio など) は置かず、答えは会話で受ける。会話の [判断] と番号・問いを揃える。
4. `python "<skill dir>/assets/check-sheet.py" <path>` で検査し、TODO の残りや相対 URL を直す。
5. 下の「シートの見せ方」で見せる。会話は結論 1 文、シートの場所、注意点、[判断] だけにする ([判断] は問いと推奨の 1 行ずつで、詳細は表に任せる)。


## シートの見せ方 (環境別)

| 環境 | 保存と表示 |
|---|---|
| `ORCA_CHAT_SCRATCH_DIR` がある | scratch内の一意な `<topic>-<英数字>.html` へ保存。詳細レポートは `-OutputPath` と `-NoOpen` を使い、`::orca-visual{file="<ファイル名>" title="<タイトル>"}` を単独行で返す。通常は別ブラウザを開かない。永続保存も依頼されていれば設定先にも保存する |
| 通常のローカル環境 | 詳細レポートは `output-config.toml` の設定先へ保存。比較シートは `./review/<topic>.html`。ブラウザを開ける場合は表示し、会話にも絶対パスのリンクを返す |
| 表示できない環境 | `-NoOpen` で保存し、絶対パスのリンクまたは利用可能なファイル受け渡し手段で渡す。表示未検証を明記 |

環境の表示規約・ユーザー指定を優先する。Codexの会話には `[タイトル](/absolute/path/report.html)` 形式でリンクする。HTML内のローカル成果物リンクは `file:///C:/path/...` 形式で、空白などをURLエンコードする。

## 参照資料

- `references/html-report.md` — 詳細レポートの生成・保存・検証
- `references/markdown-syntax.md` — 表、コード、SVG、Mermaid、バッジ、進捗バー
- `references/comparison-sheet.md` — UI比較、機械検査、表示、返答の反映
- `references/sheet-spec.md` — 比較シートのレイアウトと文章規約
- `references/preflight.md` — 比較シートを初見の読者に試問する手順

`html-report` / `save-report` が同時に選ばれても、同じ報告を重複生成しない。本スキルを入口とし、形式・保存先・承認の扱いはこの統合手順に揃える。既存スキルの設定は変更しない。
