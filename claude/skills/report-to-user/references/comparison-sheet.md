# 比較シートの手順 (見た目で比べる論点があるとき)

`<skill dir>` は SKILL.md のあるディレクトリ。詳細レポートの生成とは別の手順で、文字数の目安はこの比較シートだけに適用する。

1. **現物を把握する** — 既存 UI ならスクショかコードから忠実に再現する。ゼロからの構想なら図解でよい
2. **シートを書く** — `references/sheet-spec.md` を Read し、`assets/sheet-template.html` を埋めて `./review/<topic>.html` に保存する。版番号は付けず、やり直しでも同じファイルを上書きする。論点ごとに絵を包む要素へ `id="p1"`, `id="p2"`, … を振り、赤の ①②③ を打つ。**選択肢の対立軸は両方絵にする**
3. **推奨を書く** — 各論点の絵の下に推奨の行 (`.pick`) を書く。他案は利点があるときだけ。会話には書かない
4. **機械検査** — `python3 "<skill dir>/assets/check-sheet.py" ./review/<topic>.html` を実行する。`TODO` の残り、相対 URL、推奨の行が無い論点、文字の多すぎを検出する。NG が出たら直す
5. **試問** — `Agent` ツール (subagent) があれば、`references/preflight.md` の 5 問を文脈ゼロの subagent に出す。同期で結果を待ち、落ちた件は絵を足す・判断を落とす・言い換える。計 2 巡で打ち切る。subagent を立てられない環境では省く
6. **見せて待つ** — SKILL.md の「シートの見せ方」に従ってシートを見せる。会話には結論 1 文とシートの場所だけを書き、答えを待つ
7. **反映する** — 返事に沿って直す。必要な承認に返事がなければ待ち、推奨を承認済みと扱わない。設計が変わる指摘なら同じファイルを上書きして開き直し、捨てた案はシート内に取り消し線で残す
8. **残す** — シート HTML は消さない。コミットは依頼の範囲に従う。設計の承認をコミット依頼と解釈しない
