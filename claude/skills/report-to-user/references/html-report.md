# 詳細HTMLレポート

`<skill dir>` は SKILL.md のあるディレクトリ。PowerShell 7 (`pwsh`) を使用する。比較シートの体裁や文字数制限は適用しない。

## 種別と本文

| Kind | 対象 |
|---|---|
| review | コード・PRレビュー |
| bug | 不具合と根本原因 |
| investigation | 現状・動作の調査 |
| research | 技術調査・比較 |
| security | セキュリティ監査の結果 |
| proposal | 今後の改善・設計・仕様案 |

迷ったら `investigation`。種別は色・バッジ・保存先を決めるもので、本文の構成を強制しない。

本文は `##` を骨組みにし、必要な節だけ置く。冒頭に結果と次の行動、続いて全指摘と根拠・対応を示す。未特定の原因や未実施の検証はそのまま書く。表やコードを省略して短くしない。生成器は16行目以降の表を折りたたむが削除はしない。重要な要対応行は先頭へ並べ、重大な結論と次の行動を折りたたみの中だけに置かない。

サマリーカードは最大3つを目安とし、件数だけで埋めず「結論」「次の行動」「確認状況」を表す。色のバッジには状態の文字を添える。

## 生成

```powershell
pwsh -NoProfile -File "<skill dir>/scripts/New-HtmlReport.ps1" `
  -Kind investigation `
  -Title "認証失敗の原因と対応" `
  -Subtitle "src/auth/session.ts" `
  -BodyPath "<UTF-8本文.mdの絶対パス>" `
  -Cards "結論|原因特定","次の行動|期限判定を修正","検証|再現確認済み" `
  -NoOpen
```

| 引数 | 挙動 |
|---|---|
| `-Kind`, `-Title`, `-BodyPath` | 必須 |
| `-Subtitle`, `-Cards` | 任意。カードは `ラベル\|値\|補足` の文字列配列 |
| `-Number` | 明示番号。指定なしは既存の最大番号+1 |
| `-OutputPath` | 設定と採番より優先する明示的な保存先。Orca scratch等に使用 |
| `-NoOpen` | 保存のみ。省略するとブラウザを開く |

既定の保存先は `output-config.toml` の `~/reports/<種別サブディレクトリ>/<prefix><番号>.html`。設定は単純なセクションと `key = "value"` を扱い、汎用TOMLパーサではない。`~` はホームへ展開する。PR番号等はタイトルやカードにも記録する。`-Number` と `-OutputPath` は既存ファイルを上書きできるため、指定前に対象の存在を確認する。既存ファイルがあり更新依頼がなければ両引数を省略し、自動採番で別ファイルに保存する。

Orcaの場合は一意なscratchパスを `-OutputPath` へ渡し、必ず `-NoOpen` を付ける。永続保存も必要なら設定先への通常生成も `-NoOpen` で行う。通常環境でも表示ツールで開く場合は `-NoOpen` で二重に開くのを避ける。

## 図とリンク

表で十分なら図は不要。残したい図はインラインSVGを使う。Mermaidは必要なときだけ使い、CDNが必要なことを明示する。Mermaidなしのレポートには外部JSを読み込まない。オフラインで図も含めて残す必要がある場合はSVGを選ぶ。

記法は `markdown-syntax.md` を参照。コードは通常のコードフェンスに入れ、実行可能なHTMLとして埋め込まない。ローカル成果物へのリンクはURLエンコード済みの `file:///` を使う。ファイルの行番号はリンクの表示名やコード表記に含める。

## 出力を確かめる

- 保存されたHTMLの全指摘・表の行・コードが元の本文と対応するか確認する。
- 未置換のテンプレート変数、文字化け、リンク切れを調べる。
- ブラウザまたはレンダリング画像で、表・コード・図の欠けと横幅を確認する。表示不能なら未検証と伝える。
- 短いシート用の `check-sheet.py` はこの生成HTMLへ適用しない。生成器を変更したら `tests/Test-Parser.ps1` と `tests/Test-Generator.ps1` を `pwsh -NoProfile -File` で実行する。
