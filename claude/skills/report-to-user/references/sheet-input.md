# 報告シートの本文の書き方 (new-sheet.py の入力)

`scripts/new-sheet.py` に渡す Markdown の書式。HTML は書かない。生成器が雛形に流し込み、検査までする。

~~~text
# 要判断 1 件 | 返信チェック hook の閾値だけ決めてほしい
テスト 12 件は通過した。

```flow
# 返信が 400 字を超えたとき
期待: 返信を書く -> 会話に出る
実際: 返信を書く -> !hook が止める
```

- 要点の箇条書き (任意、5 個まで)

## 要判断: 行数の上限
推奨: 5 行のまま — 誤検知 0 件
他案: 8 行に緩める — 止まる回数が減る / 長文が会話に残る

## 項目
- [優先] 表の検出: コード内の表を誤検出する
  根拠: reply-check.mjs:17
  対応: フェンスを先に取り除く
- 単体テスト: 12 件すべて通過

## 注意点
- 実機の Stop hook では未検証

## 付録: 調査の経緯
ここはそのまま等幅で畳まれる
~~~

## 各部の決まり

| 部分 | 書き方 |
|---|---|
| タイトル | 1 行目に `# <状態の語> \| <結論 1 文>`。状態の語は 対応不要 / 要判断 n 件 / 要対応 / 未完了 |
| 補足 | タイトルの次の普通の行。結論を言い換えない補足があるときだけ |
| 次 | `次: <読み手がすること>`。要判断があれば書かない (タイトルの「要判断 n 件」で伝わる)。要判断が無く、読み手がすることも無ければ行ごと省く。「次: 特になし」「次: 対応不要」は NG |
| 図 | 流れ・食い違い・前後は `flow`、主体間のやり取りは `sequence`、量は `bars` のフェンスで書く。生成器が SVG を描く。記法で描けない形は `svg` に書き、要点を `<g class="key">` で包む。色は雛形の CSS が付ける。冒頭に 1 枚置き、図で速く伝わる所には自由な節にも足す |
| 要判断 | 1 問につき `## 要判断: <問い>` の節を 1 つ。1 行目は `推奨:`、他案は利点のある案だけ `他案: <案> — <利点> / <代償>` |
| 項目 | `## 項目` の下に `- [ラベル] 名前: 内容`。ラベルは確認済みでない行にだけ付ける。内容は「点線の灰」のような名詞だけにせず、変更前と変更後、または何が起きるかを 1 文で書く。`優先` は赤、`未検証` は濃い札、`推測` は点線の灰色の札、他は灰色の札になる。`確認済み` と書いても札は出ない。項目は表ではなく、ラベルごとのまとまりに 1 行の見出し (名前と内容) で並ぶ。順は `優先`、ラベル無し (見出しは「そのほか」)、その他のラベル、`推測`・`未検証`。まとまりが 1 つだけなら見出しは出ない。`根拠:` と `対応:` は行を開いたときに出し、`優先` の行は最初から開く。続き行に `根拠:` (複数可) と `対応:` を字下げして書く。`根拠:` は file:line や参照 URL など読み手が開けるものがある行だけに書き、通過した検証のコマンドは書かない。`対応:` はこれから誰かがすることのある行だけに書き、「特になし」「引き続き注視」「念のため確認」のような埋め草は書かない。`## 項目: 関数 / 何をするか` の列名は 2 つまで受け付けるが (3 つ以上は NG)、画面には出ない。根拠の行でも行内の書式が使える |
| 注意点 | `## 注意点` の下に箇条書き。失敗したテスト・飛ばした作業・未確認のこと |
| 付録 | `## 付録: <中身と分量>`。経緯・ログを等幅のまま畳む。判断や行動に要る項目は入れない |
| 自由な節 | 上のどれでもない `## <見出し>`。中は下の「自由な節の記法」で書く。調査の説明、長い表、コード、Mermaid の図に使う |

シートの色は 1 色に 1 つの意味だけを持たせる。琥珀は読み手が決める所 (要判断、選んだ案)、赤は読み手が動く所 (`優先`、要対応、図の `key`) に使い、それ以外は灰色で出す。札の `[!yellow]` `[!green]` などは書き手が選ぶ色なので、この割り当ての外にある。

行の中では `` `code` ``、`**太字**`、`[文字](https://...)` が使える。それ以外の記号はエスケープされる。

## 字数の上限

本文 800 字、結論 (タイトル) 60 字、表のセルと項目の内容・`対応:` は 60 字 (根拠の行は数えない)、要点の箇条書き 5 個。結論 60 字超、箇条書き 6 個以上、「次:」の埋め草は生成器が `NG` で止める。経緯・手順・ログは `## 付録` に畳む。読み手の判断に要る情報は畳まない。

本文の文章 (付録・図・コードを除く) が 800 字を超えると、生成器は自動で詳細の形にする。詳細では本文 800 字・セル 60 字・箇条書き 5 個の目安を外し、`output-config.toml` の保存先へ連番で残す。図の決まりは詳細でも変わらない (下の「図の選び方」)。結論 60 字と「次:」の埋め草は詳細でも NG になる。NG のときは保存先にも一覧にも書かず、直す材料として scratch (Orca の外では一時ディレクトリ) にだけ置く。形は呼び出し側で選べない。種別 (review / bug / security / proposal / research / investigation) はタイトルと見出しの語から `infer_kind()` が決めるので、種別が伝わる語をタイトルに入れる。

## 自由な節の記法

| 記法 | 書き方 |
|---|---|
| 段落・小見出し | 普通の行と `### 小見出し`。`#` と `##` は使えない |
| リスト | `- ` と `1. `。字下げで入れ子になる (幅は 2 でも 4 でもよい) |
| 表 | `\| 列 \| 列 \|` と区切り行。セル内の縦棒は前にバックスラッシュを付ける。16 行目以降は畳まれる |
| コード | 言語名付きのフェンス。中身はエスケープされる |
| 図 | `flow`、`sequence`、`bars` (下の「図の記法」)、`svg` (色は雛形の CSS が付ける)、`mermaid` (CDN から読むのでオフラインでは定義のまま表示される)。残したい図は生成器が描く記法か SVG を使う |
| 差分 | ` ```diff ` のフェンス。`+` の行は淡い地、`-` の行は灰色の取り消し線で、`@@` の行は灰色で出る。`>> [優先] 指摘` の行は直前の行に付く注記になり、指した行は `優先` なら赤、それ以外は灰色で塗られる。見出しを `@@ -a,b +c,d @@` か `@@ path:行 @@` にすると左に行番号が付き、`path:行` はエディタで開くリンクになる。コードを抜き出して指摘するときは `@@ path:行 @@` を使い、続く行は抜けなく並べる。この抜粋では `+` `-` で始まる行も色を付けず、1 行ずつ数える |
| 引用 | `> ` で始まる行 |
| 横棒 | `:::bar ラベル\|85` (0〜100 の割合) |
| 札 | `[!red 重大]` `[!yellow 中]` `[!green 済]` `[!blue 情報]` `[!gray 保留]` |

根拠の行やコード表記の `path:line` は、ファイルが実在すればエディタの該当行を開くリンク (`vscode://file/...`) になる。パスはリポジトリのルートからの相対で書く。要判断の案の行は押すと選ばれ、コードブロックにはコピーボタンが自動で付く。

生成器が自動で付けるものは次のとおり。本文には何も書かなくてよい。

| 付くもの | 条件と働き |
|---|---|
| 生成時刻とリポジトリの版 | タイトル上の小さな行に、日時・リポジトリ名・`ブランチ@短い SHA` を出す |
| 返答のコピー | 最後の要判断の下にボタンを 1 つだけ置く (要判断が 1 問でも置く)。押す前は各問の推奨が選ばれていて、案の行を押すと選び直せる。ボタンは選んだ案を 1 つの返答にしてコピーする |
| 依頼のコピー | `対応:` のある行の対応案に付く。「「名前」を対応して: 対応案 (根拠: …)」の 1 文をコピーする |
| 前回との差分 | 同じ `--name` (または同じ `--out`) で作り直すと、前回に無かった行に「新」の札を付け、前回にあって今回ない行をページの中で 1 か所に畳んで並べる。行は名前で見分けるので、内容だけ書き直した行には「新」が付かない。同じ名前の行が 2 つあれば、2 つ目からは「名前#2」として見分ける。前回は scratch の写しと保存先の同じ `--name` の版から、最後に書いたものを選ぶ |
| 要判断と優先の数 | 詳細の形のとき、上に留めて出す。押すと最初のものへ飛ぶ |
| 印刷 | 印刷・PDF ではボタンを隠し、畳みをすべて開く |
| 保存先の一覧 | 詳細と `--save` のとき、`output-config.toml` の保存先の直下に `index.html` を作り直す。種別・状態・語で絞り込める。状態が要対応・未完了のレポートに残る優先の項目も並べる。同じ `--name` で作り直した版が複数あれば、優先の項目は最新の版からだけ集める (古い版も一覧の表には残る) |

ページには機械向けの要約 (`<script type="application/json" id="report-data">`) が入る。前回との差分と保存先の一覧はこれを読む。

行の中では `*斜体*` も使える。リンクは `https:` `http:` `mailto:` `file:///` `#` `/` `.` で始まるものだけが有効で、それ以外は文字だけ残る。SVG の `<script>`、`on*` 属性、`javascript:` は取り除かれる。

## 図の記法

座標を書かずに図を足すための記法。生成器が幅と折り返しを計算して SVG にする。どちらも `!` を前に付けた要素を要点として赤くし、`# ` で始まる行を図の上に出す条件の文にする。

` ```flow ` は 1 行が 1 段で、箱を `->` でつなぐ。`段名: ` で始めると左端に段の名前が出る。続く段で同じ列の箱がどちらも `!` なら縦の点線で結ぶので、食い違いの型は 2 段を同じ列数で書く。前後の型は `前:` と `後:` の 2 段にし、変わった箱に `!` を付ける。1 段だけなら流れの型になる。

~~~text
```flow
# 書き込みが失敗したとき
画面: 保存を押す -> 「保存しました」と出る -> !一覧に記事が出る
実際: 保存を押す -> 書き込みに失敗 -> !一覧に記事が無い
```
~~~

` ```bars ` は 1 行が 1 本で、`ラベル | 値` と書く。値の最初の数で棒の長さを決め、値の文字 (単位を含む) はそのまま棒の端に出す。目盛りは図の中の最大値にそろう。

~~~text
```bars
# 閾値ごとに残る差し戻し
今 (5 行・300 字) | 158 回
!7 行・400 字 | 88 回
```
~~~

````md
```sequence
# 応答が届かず、再試行で同じ記事が 2 件できる
@steps
画面 | サーバー
画面 -> サーバー | 保存を依頼 | 記事が 1 件できる
サーバー -x 画面 | 応答が届かない
!画面 -> サーバー | 再試行 | 保存済みの記事が重複する
```
````

`sequence` は登場主体を `|` で並べ、次の行から「送り手 -> 受け手 | やり取り | 注釈」と書く。やり取りは上から時間順。届かなかった応答は `-x` を使い、注釈が要る行だけ 3 欄目を書く。`!` はその行の矢印と注釈を強調する。図の前提や結論は `# ` で始まる行に書ける。段階を選んで追うことに意味がある図では、登場主体の前に `@steps` を置く。最初は全体を表示し、段階を選ぶとその箇所を強調する。印刷と JavaScript が使えない表示でも、全体と注釈は読める。

構成の入れ子や状態の格子は記法では描けないので、` ```svg ` で書く。

## 図の選び方

描く前に「この図だけで何が分かるか」を 1 文で言う。伝えたい関係に合わせて下の表から型を選ぶ。変化や異常の理由は、その場所のそばに短く書く。文や表の方が速く伝わる内容は文章のままにする。

図にはタイトルの結論そのものを描く。読み手は図を最初に見るので、図だけで「何が起きるか」が分かるようにする。シートでも詳細でも図は省かない。冒頭に全体の図を 1 枚置き、そのあとは下の「図を足す所」に当てはまる箇所ごとに図を足す。枚数の上限は無く、文で読むより図で見る方が速い所にはすべて描く。逆に、形の無い内容 (理由の説明、1 行で済む事実) を図にしない。指摘が多いときの冒頭の図は、読み手が使う流れの段 (作る・保存する・見る など) に指摘を振り分け、指摘が集まる段を赤くする。コードの処理の流れや部品の構成を描いて問題の段に印を付けただけの図は、どこで起きるかは分かっても、何が起きるかは分からない。不具合やレビューの指摘なら、利用者がする操作、画面に出ること、実際の状態を箱にする。関数名や変数名は図に入れず、表と「指摘の箇所」に書く。

| 要点の形 | 型 | 描き方 |
|---|---|---|
| 表示や期待と実際がずれる (不具合・レビューの指摘の多く) | 食い違い | `flow` の 2 段。上の段に「画面に出ること」または「期待」、下の段に「実際」を時間の順に並べ、ずれる箇所を縦の点線で結んで両方を赤くする。左端に段の名前、上に起きる条件を書く |
| 変更の前と後で何かが違う | 前後 | `flow` の `前:` `後:` の 2 段。前と後を同じ配置で上下に並べ、変わった要素だけ赤くする |
| 利用者の操作の順に起きることが要点 | 流れ | `flow` の 1 段。箱を矢印でつなぎ、問題や変更のある段だけ赤くする。箱は利用者から見える操作と結果にし、コードの関数を並べない |
| 誰が誰に何を送り、どの応答や処理で結果が変わるかが要点 | やり取り | `sequence`。主体ごとに列を作り、上から時間順に並べる。結論に関わる行に注釈を添え、段階を追う必要があれば `@steps` を付ける |
| 部品のどれかに関わる | 構成 | 部品を入れ子や隣り合わせの箱で描き、該当の部品だけ赤くする。全部の部品が同じ重みなら描かない |
| 数や大きさに差がある | 量 | `bars`。横棒を同じ目盛りで並べ、数値を棒の端に書く。注目の 1 本だけ赤くする |
| 多くの項目に済み・未了が混ざる | 状態の格子 | 項目を升目に並べ、状態を文字で入れる。優先する升だけ赤くする |

### 同じ不具合を描き分ける

「利用者に何が起きるか」を伝えるなら、期待した結果と実際の結果を同じ列で比べる。

````md
```flow
# 保存の応答が届かず、画面が再試行したとき
期待: 保存を押す -> !記事が 1 件できる
実際: 保存を押す -> !同じ記事が 2 件できる
```
````

「なぜ 2 件できるか」まで伝えるなら、上の `sequence` の作例のように、依頼と応答を送った向きに描く。「再試行」のそばに保存済みの記事が重複することを書く。影響と原因の両方が必要な報告では、冒頭に結果の差を置き、原因の節でやり取りを示す。図が長くなる場合も、結果が変わる段階は冒頭の図に残す。箱には「画面」のように読み手が分かる名前を使い、矢印には「保存を依頼」のように、何を渡すか書く。詳細な API 名は必要な箇所に添える。

生成した `sequence` は、図の下から同じやり取りを文章でも読める。公開前に、矢印の向き、注釈の位置、色を区別できなくても異常が読み取れるかを確認する。`@steps` を付けたら、全体を表示した状態で結論が分かるか、選んだ段階に視線が移るかを確かめる。

### 図を足す所

冒頭の図とは別に、次の箇所には図を足す。要判断の節には「推奨:」「他案:」の行しか書けないので、図は自由な節に置く。

| 箇所 | 型 | 置き方 |
|---|---|---|
| `優先` の指摘 (冒頭の図で描いたものを除く) | 食い違い | `## 重い n 件で何が起きるか` の下に `### 指摘の名前` と図を 1 件ずつ |
| 案によって結果の形が変わる要判断 | 前後 | `## 案の違い` に、案ごとの結果を同じ配置で並べる |
| 数・字数・時間・件数を比べる指摘や説明 | 量 | その説明の自由な節に、同じ目盛りの横棒を置く |
| 手順・仕組み・構成を説明する自由な節 | 流れ / 構成 | その節の先頭に置き、文はその補足にする |

箱に `## 項目` の行と同じ語を入れて並べただけの図は、表と同じ内容になるので描かない (例: ディレクトリ構成を聞かれて、3 つのフォルダ名と中身を箱に書き写す)。項目の名前が 3 つ以上あり、その 6 割以上 (かつ 2 つ以上) が SVG の文字にそのまま出ると、検査が `??` を出す。Mermaid の図は描画前に文字を読めないので見ない。図が無いとき、`優先` が 2 件以上あるのに図がその件数より少ないときも `??` を出す (シートと詳細のどちらでも)。要判断が主役で項目が 3 行以下のシートは図を求めない。
