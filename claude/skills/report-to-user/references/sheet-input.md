# 報告シートの本文の書き方 (new-sheet.py の入力)

`scripts/new-sheet.py` に渡す Markdown の書式。HTML は書かない。生成器が雛形に流し込み、検査までする。

~~~text
# 要判断 1 件 | 返信チェック hook の閾値だけ決めてほしい
テスト 12 件は通過した。
次: 閾値を 5 行のままにするか選ぶ

```svg
<svg viewBox="0 0 960 200" width="100%" role="img" aria-label="流れ">
  <g><rect x="20" y="70" width="200" height="60" rx="8"/><text x="120" y="105" text-anchor="middle">返信を書く</text></g>
  <g class="key"><rect x="380" y="70" width="200" height="60" rx="8"/><text x="480" y="105" text-anchor="middle">hook が止める</text></g>
</svg>
```

- 要点の箇条書き (任意、5 個まで)

## 要判断: 行数の上限
推奨: 5 行のまま — 誤検知 0 件
他案: 8 行に緩める — 止まる回数が減る / 長文が会話に残る

## 項目
- [先に対応] 表の検出: コード内の表を誤検出する
  根拠: reply-check.mjs:17
  対応: フェンスを先に取り除く
- [確認済み] 単体テスト: 12 件すべて通過
  根拠: node --test claude/hooks/reply-check.test.mjs

## 注意点
- 実機の Stop hook では未検証

## 付録: 実行ログ
ここはそのまま等幅で畳まれる
~~~

## 各部の決まり

| 部分 | 書き方 |
|---|---|
| タイトル | 1 行目に `# <状態の語> \| <結論 1 文>`。状態の語は 対応不要 / 要判断 n 件 / 要対応 / 未完了 |
| 補足 | タイトルの次の普通の行。結論を言い換えない補足があるときだけ |
| 次 | `次: <読み手がすること>`。省くと「対応不要」 |
| 図 | ` ```svg ` のフェンスに `<svg>` をそのまま書く。要点だけ `<g class="key">` で包む。2 枚まで。色は雛形の CSS が付けるので `fill` や `stroke` を書かない |
| 要判断 | 1 問につき `## 要判断: <問い>` の節を 1 つ。1 行目は `推奨:`、他案は利点のある案だけ `他案: <案> — <利点> / <代償>` |
| 項目 | `## 項目` の下に `- [ラベル] 名前: 内容`。ラベルは行によって状態が違うときだけ付ける。`先に対応` は赤、`推測` は琥珀、他は灰色の札になる。続き行に `根拠:` (複数可) と `対応:` を字下げして書く。`対応:` が 1 行でもあれば 3 列目「対応案」が付く。列名を変えるときは `## 項目: 関数 / 何をするか` |
| 注意点 | `## 注意点` の下に箇条書き。失敗したテスト・飛ばした作業・未確認のこと |
| 付録 | `## 付録: <中身と分量>`。経緯・ログを等幅のまま畳む。判断や行動に要る項目は入れない |

行の中では `` `code` ``、`**太字**`、`[文字](https://...)` が使える。それ以外の記号はエスケープされる。
