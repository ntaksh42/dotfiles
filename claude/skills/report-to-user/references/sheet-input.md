# 報告シートの本文の書き方 (new-sheet.py の入力)

`scripts/new-sheet.py` に渡す Markdown の書式。HTML は書かない。生成器が雛形に流し込み、検査までする。

~~~text
# 要判断 1 件 | 返信チェック hook の閾値だけ決めてほしい
テスト 12 件は通過した。

```svg
<svg viewBox="0 0 960 200" width="100%" role="img" aria-label="流れ">
  <g><rect x="20" y="70" width="200" height="60" rx="8"/><text x="120" y="105" text-anchor="middle">返信を書く</text></g>
  <g class="key"><rect x="380" y="70" width="200" height="60" rx="8"/><text x="480" y="105" text-anchor="middle">hook が止める</text></g>
</svg>
```

- 要点の箇条書き (任意、5 個まで)

## 要判断: 行数の上限
推奨: 5 行のまま — 誤検知 0 件
他案: 8 行に緩める — 止まる回数が減る / 長文が会話に残る

## 項目
- [優先] 表の検出: コード内の表を誤検出する
  根拠: reply-check.mjs:17
  対応: フェンスを先に取り除く
- 単体テスト: 12 件すべて通過

## 注意点
- 実機の Stop hook では未検証

## 付録: 調査の経緯
ここはそのまま等幅で畳まれる
~~~

## 各部の決まり

| 部分 | 書き方 |
|---|---|
| タイトル | 1 行目に `# <状態の語> \| <結論 1 文>`。状態の語は 対応不要 / 要判断 n 件 / 要対応 / 未完了 |
| 補足 | タイトルの次の普通の行。結論を言い換えない補足があるときだけ |
| 次 | `次: <読み手がすること>`。要判断があれば書かない (タイトルの「要判断 n 件」で伝わる)。要判断が無く、読み手がすることも無ければ行ごと省く。「次: 特になし」「次: 対応不要」は NG |
| 図 | ` ```svg ` のフェンスに `<svg>` をそのまま書く。要点だけ `<g class="key">` で包む。既定で 1 枚、多くても 2 枚 (下の「図の選び方」)。色は雛形の CSS が付けるので `fill` や `stroke` を書かない。量の図の棒は `<rect class="bar">` にすると塗られる |
| 要判断 | 1 問につき `## 要判断: <問い>` の節を 1 つ。1 行目は `推奨:`、他案は利点のある案だけ `他案: <案> — <利点> / <代償>` |
| 項目 | `## 項目` の下に `- [ラベル] 名前: 内容`。ラベルは確認済みでない行にだけ付ける。内容は「点線の灰」のような名詞だけにせず、変更前と変更後、または何が起きるかを 1 文で書く。`優先` は赤、`未検証` は濃い札、`推測` は点線の灰色の札、他は灰色の札になる。`確認済み` と書いても札は出ない。`優先` の行があり項目が 6 行以上なら、残りの行は「ほかの n 件」に畳まれる。続き行に `根拠:` (複数可) と `対応:` を字下げして書く。`根拠:` は file:line や参照 URL など読み手が開けるものがある行だけに書き、通過した検証のコマンドは書かない。`対応:` はこれから誰かがすることのある行だけに書き、「特になし」「引き続き注視」「念のため確認」のような埋め草は書かない。`対応:` が 1 行でもあれば 3 列目「対応案」が付く。列名を変えるときは `## 項目: 関数 / 何をするか` と 2 つだけ書く (3 つ以上は NG)。根拠の行でも行内の書式が使える |
| 注意点 | `## 注意点` の下に箇条書き。失敗したテスト・飛ばした作業・未確認のこと |
| 付録 | `## 付録: <中身と分量>`。経緯・ログを等幅のまま畳む。判断や行動に要る項目は入れない |
| 自由な節 | 上のどれでもない `## <見出し>`。中は下の「自由な節の記法」で書く。調査の説明、長い表、コード、Mermaid の図に使う |

シートの色は 1 色に 1 つの意味だけを持たせる。琥珀は読み手が決める所 (要判断、選んだ案)、赤は読み手が動く所 (`優先`、要対応、図の `key`) に使い、それ以外は灰色で出す。札の `[!yellow]` `[!green]` などは書き手が選ぶ色なので、この割り当ての外にある。

行の中では `` `code` ``、`**太字**`、`[文字](https://...)` が使える。それ以外の記号はエスケープされる。

## 字数の上限

本文 800 字、結論 (タイトル) 60 字、表のセル 60 字 (根拠の行は数えない)、要点の箇条書き 5 個。結論 60 字超、箇条書き 6 個以上、「次:」の埋め草は生成器が `NG` で止める。経緯・手順・ログは `## 付録` に畳む。読み手の判断に要る情報は畳まない。

本文の文章 (付録・図・コードを除く) が 800 字を超えると、生成器は自動で詳細の形にする。詳細では本文 800 字・セル 60 字・箇条書き 5 個の目安を外し、`output-config.toml` の保存先へ連番で残す。図の決まりは詳細でも変わらない (下の「図の選び方」)。結論 60 字と「次:」の埋め草は詳細でも NG になる。NG のときは保存先にも一覧にも書かず、直す材料として scratch (Orca の外では一時ディレクトリ) にだけ置く。形は呼び出し側で選べない。種別 (review / bug / security / proposal / research / investigation) はタイトルと見出しの語から `infer_kind()` が決めるので、種別が伝わる語をタイトルに入れる。

## 自由な節の記法

| 記法 | 書き方 |
|---|---|
| 段落・小見出し | 普通の行と `### 小見出し`。`#` と `##` は使えない |
| リスト | `- ` と `1. `。字下げで入れ子になる (幅は 2 でも 4 でもよい) |
| 表 | `\| 列 \| 列 \|` と区切り行。セル内の縦棒は前にバックスラッシュを付ける。16 行目以降は畳まれる |
| コード | 言語名付きのフェンス。中身はエスケープされる |
| 図 | ` ```svg ` (色は雛形の CSS が付ける) か ` ```mermaid ` (CDN から読むのでオフラインでは定義のまま表示される)。残したい図は SVG にする |
| 差分 | ` ```diff ` のフェンス。`+` の行は淡い地、`-` の行は灰色の取り消し線で、`@@` の行は灰色で出る。`>> [優先] 指摘` の行は直前の行に付く注記になり、指した行は `優先` なら赤、それ以外は灰色で塗られる。見出しを `@@ -a,b +c,d @@` か `@@ path:行 @@` にすると左に行番号が付き、`path:行` はエディタで開くリンクになる。コードを抜き出して指摘するときは `@@ path:行 @@` を使い、続く行は抜けなく並べる。この抜粋では `+` `-` で始まる行も色を付けず、1 行ずつ数える |
| 引用 | `> ` で始まる行 |
| 横棒 | `:::bar ラベル\|85` (0〜100 の割合) |
| 札 | `[!red 重大]` `[!yellow 中]` `[!green 済]` `[!blue 情報]` `[!gray 保留]` |

根拠の行やコード表記の `path:line` は、ファイルが実在すればエディタの該当行を開くリンク (`vscode://file/...`) になる。パスはリポジトリのルートからの相対で書く。要判断の案の行は押すと選ばれ、コードブロックにはコピーボタンが自動で付く。

生成器が自動で付けるものは次のとおり。本文には何も書かなくてよい。

| 付くもの | 条件と働き |
|---|---|
| 生成時刻とリポジトリの版 | タイトル上の小さな行に、日時・リポジトリ名・`ブランチ@短い SHA` を出す |
| 返答のコピー | 最後の要判断の下にボタンを 1 つだけ置く (要判断が 1 問でも置く)。押す前は各問の推奨が選ばれていて、案の行を押すと選び直せる。ボタンは選んだ案を 1 つの返答にしてコピーする |
| 依頼のコピー | `対応:` のある行の対応案に付く。「「名前」を対応して: 対応案 (根拠: …)」の 1 文をコピーする |
| 前回との差分 | 同じ `--name` (または同じ `--out`) で作り直すと、前回に無かった行に「新」の札を付け、前回にあって今回ない行をページの中で 1 か所に畳んで並べる。行は名前で見分けるので、内容だけ書き直した行には「新」が付かない。同じ名前の行が 2 つあれば、2 つ目からは「名前#2」として見分ける。前回は scratch の写しと保存先の同じ `--name` の版から、最後に書いたものを選ぶ |
| 要判断と優先の数 | 詳細の形のとき、上に留めて出す。押すと最初のものへ飛ぶ |
| 印刷 | 印刷・PDF ではボタンを隠し、畳みをすべて開く |
| 保存先の一覧 | 詳細と `--save` のとき、`output-config.toml` の保存先の直下に `index.html` を作り直す。種別・状態・語で絞り込める。状態が要対応・未完了のレポートに残る優先の項目も並べる。同じ `--name` で作り直した版が複数あれば、優先の項目は最新の版からだけ集める (古い版も一覧の表には残る) |

ページには機械向けの要約 (`<script type="application/json" id="report-data">`) が入る。前回との差分と保存先の一覧はこれを読む。

行の中では `*斜体*` も使える。リンクは `https:` `http:` `mailto:` `file:///` `#` `/` `.` で始まるものだけが有効で、それ以外は文字だけ残る。SVG の `<script>`、`on*` 属性、`javascript:` は取り除かれる。

## 図の選び方

描く前に「この図だけで何が分かるか」を 1 文で言う。言えないなら図を省く。要点が持つ形に合わせて型を 1 つ選び、文字を消しても形だけで意味が通る図にする。説明は図のラベルに書く。

図にはタイトルの結論そのものを描く。読み手は図を最初に見るので、図だけで「何が起きるか」が分かるようにする。本文が長い詳細の形でも図は省かない。冒頭に全体の図を 1 枚置き、`優先` の指摘が 2 件以上あるときは、重い指摘ごとに 1 枚ずつ「食い違い」の図を自由な節 (例: `## 重い n 件で何が起きるか` の下に `### 指摘の名前` と図) に置く。指摘が多いときの冒頭の図は、読み手が使う流れの段 (作る・保存する・見る など) に指摘を振り分け、指摘が集まる段を赤くする。コードの処理の流れや部品の構成を描いて問題の段に印を付けただけの図は、どこで起きるかは分かっても、何が起きるかは分からない。不具合やレビューの指摘なら、利用者がする操作、画面に出ること、実際の状態を箱にする。関数名や変数名は図に入れず、表と「指摘の箇所」に書く。

| 要点の形 | 型 | 描き方 |
|---|---|---|
| 表示や期待と実際がずれる (不具合・レビューの指摘の多く) | 食い違い | 上の段に「画面に出ること」または「期待」、下の段に「実際」を時間の順に並べ、ずれる箇所を縦の点線で結んで両方を赤くする。左端に段の名前、上に起きる条件を書く |
| 変更の前と後で何かが違う | 前後 | 同じ配置の図を左右に並べ、変わった要素だけ赤くする |
| 利用者の操作の順に起きることが要点 | 流れ | 箱を矢印でつなぎ、問題や変更のある段だけ赤くする。箱は利用者から見える操作と結果にし、コードの関数を並べない |
| 部品のどれかに関わる | 構成 | 部品を入れ子や隣り合わせの箱で描き、該当の部品だけ赤くする。全部の部品が同じ重みなら描かない |
| 数や大きさに差がある | 量 | 横棒を同じ目盛りで並べ、数値を棒の端に書く。棒は `<rect class="bar">`。注目の 1 本だけ赤くする |
| 多くの項目に済み・未了が混ざる | 状態の格子 | 項目を升目に並べ、状態を文字で入れる。優先する升だけ赤くする |

箱に `## 項目` の行と同じ語を入れて並べただけの図は、表と同じ内容になるので描かない (例: ディレクトリ構成を聞かれて、3 つのフォルダ名と中身を箱に書き写す)。項目の名前が 3 つ以上あり、その 6 割以上 (かつ 2 つ以上) が SVG の文字にそのまま出ると、検査が `??` を出す。Mermaid の図は描画前に文字を読めないので見ない。図が無いとき、詳細で `優先` が 2 件以上あるのに図が 1 枚以下のときも `??` を出す。要判断が主役で項目が 3 行以下のシートは図を求めない。
