# 比較シートの手順 (見た目で比べる論点があるとき)

`<skill dir>` の意味は SKILL.md の「比較シートの手順」の冒頭を参照。

1. **現物を把握する** — 既存 UI ならスクショかコードから忠実に再現する。ゼロからの構想なら図解でよい
2. **シートを書く** — `references/sheet-spec.md` を Read し、`assets/sheet-template.html` を埋めて `./review/<topic>.html` に保存する。版番号は付けず、やり直しでも同じファイルを上書きする。論点ごとに絵を包む要素へ `id="p1"`, `id="p2"`, … を振り、赤の ①②③ を打つ。**選択肢の対立軸は両方絵にする**
3. **[判断] の JSON を書く** — `[{"selector": "#p1", "body": "[判断] …"}]` の形で scratchpad (無ければ一時ディレクトリ) に保存する。`selector` はその判断が指す論点の id
4. **機械検査** — `python3 "<skill dir>/assets/check-sheet.py" ./review/<topic>.html --comments <json>` を実行する。`TODO` の残り、相対 URL、論点の無い [判断]、推奨の書き忘れ、文字の多すぎを検出する。NG が出たら直す
5. **試問** — `Agent` ツール (subagent) があれば、`references/preflight.md` の 5 問を文脈ゼロの subagent に出す。同期で結果を待ち、落ちた件は絵を足す・判断を落とす・言い換える。計 2 巡で打ち切る。subagent を立てられない環境では省く
6. **開いて聞く** — SKILL.md の「シートの見せ方」に従ってシートを見せる。続けて会話で [判断] を聞く
7. **反映する** — 返事に沿って直す。返事の無い [判断] は推奨で確定する。設計が変わる指摘なら同じファイルを上書きして開き直し、捨てた案はシート内に取り消し線で残す
8. **残す** — シート HTML は消さない。git 管理下ならシートの commit を勧める (「なぜこの設計か」の答えになる)。反映後のコードの commit は人に確認してから
