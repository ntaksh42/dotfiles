小さなシェルスクリプトにも set -euo pipefail を付ける理由

数行のシェルスクリプトは「動けばいい」と思いがちです。しかし失敗を黙って通す設定のまま育つと、あとで原因を追うのに何倍も時間がかかります。この記事では、最初の 1 行で防げる 3 種類の事故を紹介します。

1. コマンドの失敗を見逃す (-e)

既定のシェルは、途中のコマンドが失敗しても次の行へ進みます。ビルドが失敗したのにデプロイまで走ってしまう、という事故はほぼこれが原因です。

#!/usr/bin/env bash
set -euo pipefail
make build      # ここで失敗したら
./deploy.sh     # ここは走らない

-e を付けると、失敗したコマンドの直後でスクリプト全体が止まります。止まる場所が失敗した場所と一致するので、ログを上から読む必要がありません。

2. 未定義の変数を空文字として使う (-u)

変数名を 1 文字打ち間違えると、シェルはそれを「空の文字列」として扱います。rm -rf "$BUILD_DIR/" のつもりが rm -rf "/" になる、という有名な事故がこの型です。

-u を付けると、未定義の変数を参照した時点でエラーになります。打ち間違いは実行前ではなく実行時に見つかりますが、それでも何も起きないよりはずっと早い発見です。

3. パイプの途中の失敗を隠す (-o pipefail)

パイプでつないだコマンド列の終了ステータスは、既定では最後のコマンドのものだけです。curl が失敗しても、後ろの grep が成功すれば全体は成功扱いになります。

パイプの左側は「素材の取得」、右側は「加工」であることが多い。素材の取得が失敗したら、加工が成功しても意味がない。

-o pipefail を付けると、パイプ内のどれか 1 つでも失敗すれば全体が失敗になります。

まとめ

  • -e: 失敗したら止まる
  • -u: 未定義の変数はエラー
  • -o pipefail: パイプの途中の失敗も失敗

3 つとも 1 行で済みます。次に新しいスクリプトを作るときは、shebang の次の行に書いてから本文を書き始めてください。
