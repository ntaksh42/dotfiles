# verify-before-done

主張の前に証拠を取る。このメッセージの中で検証を実行していなければ、通るとは書かない。

## 報告の前の 4 段

1. 決める: この主張を裏付けるコマンドや観察は何か
2. 実行する: そのコマンドを省略せずに今実行する。前回の実行結果を流用しない
3. 読む: 出力を最後まで読み、終了コードと失敗の件数を確かめる
4. 書く: 出力が主張を裏付けるなら、件数などの結果を添えて書く。裏付けないなら、実際の状態をそのまま書く

## 主張ごとに要る証拠

| 主張 | 要る証拠 | 足りないもの |
|---|---|---|
| テストが通る | テストコマンドの出力で失敗 0 件 | 前回の実行、「通るはず」 |
| ビルドできる | ビルドコマンドの終了コード 0 | lint の通過、ログの見た目 |
| 不具合が直った | 元の再現手順で症状が出ない | コードを変えたこと |
| 回帰テストが効く | 修正を戻すと失敗し、戻すと通る | 1 回通ったこと |
| 委譲した作業が済んだ | `git diff` で変更を見て、検証を自分で流す | サブエージェントの「完了」報告 |
| 要件を満たした | 依頼や計画書を読み直し、項目ごとに照らす | テストが通ったこと |
| hook・設定が効く | 実際に発火させた出力やログ | ファイルを置いたこと |

## 止まる合図

次に気づいたら、報告を書く前に検証へ戻る。

- 「はず」「おそらく」「よさそう」で状態を書こうとしている
- 検証の前に「完了しました」と書き出している
- 一部だけ確かめて全体について書こうとしている
- サブエージェントの報告をそのまま転記しようとしている

## 検証できないとき

環境が無い、時間がかかりすぎる、実機でしか確かめられない、といった理由で検証できない項目は、未検証と明記して理由を添える。検証できた項目と混ぜて「完了」とまとめない。
